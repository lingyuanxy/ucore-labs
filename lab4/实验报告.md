## 模块一 · 虚拟内存页操作

**规格。** `page_insert()` 建立或替换 4 KiB 映射。同一地址重新映射到同一页时仅更新权限，物理页引用计数不变。替换时更新新页引用，在旧映射失效后减少旧页引用，最后一个引用消失才释放。`page_remove()` 对未映射地址可重复调用。页表页分配失败返回 `-E_NO_MEM`，恢复本次新建的中间目录。

**提示词**

> 按 2026 Lab4 的 `pmm.c` 接口实现页插入和移除。沿用现有 `get_pte`、`pte_create`、引用计数和 PMM 接口。逐一考虑首次映射、同页更新权限、换页、重复删除、两级页表分配中途失败。更新页表后执行合适的 `sfence.vma`，并验证页表项、引用计数、空闲页计数一致。

**实现分析。** `get_pte()` 用三个 9 位索引逐级定位映射。新目录和叶子表分两次分配，第二次失败会撤销本次新建的目录。Sv39 的写映射同时设置读权限，默认权限 0 建立可读叶子；中间页表项仅设置 `V`。替换先写入新 PTE 并使旧翻译失效，再归还旧页。临时 1 GiB 启动映射在切换到新的页表后退出使用。

## 模块二 · 进程创建与初始化

**规格。** `alloc_proc()` 初始化 PCB。启动线程使用原有启动栈。新线程使用独立内核栈，拥有唯一的现存 PID；先登记链表与哈希表，再唤醒。分配失败返回负错误码，逆序归还已取得的资源。内核线程共享内核页表。

**提示词**

> 实现 `alloc_proc`、`proc_init`、`kernel_thread`、`do_fork`、`copy_thread`、`copy_mm`。复用已有栈分配和 PID 接口。以启动现场建立 PID 0 的 idle，使用函数和参数构造临时 Trap frame，再建 PID 1 的 init。写清 PCB、栈、页表、PID、链表、状态的建立顺序，保证失败清理与第一次运行路径正确。

**实现分析。** `kernel_thread()` 将入口函数、参数和 `kernel_thread_entry` 分别放入 `s0`、`s1` 和 `epc`。`copy_thread()` 将 Trap frame 放到新线程内核栈顶附近，并设置 `context.ra = forkret`、`context.sp = tf`。第一次切换后从 `forkret → forkrets → __trapret → kernel_thread_entry` 恢复并调用线程函数。分配 PID 时按 `MAX_PID` 回绕，通过 `proc_list` 避开已占用值。`next_safe` 记录下一处可能冲突的上界，因此唯一性针对现存进程。

## 模块三 · 调度与上下文切换

**规格。** idle 检测到重调度请求后进入调度器。调度器循环扫描从当前位置之后开始的进程链表，选择可运行对象；无可运行对象时回到 idle。切换期间保持本核中断状态受控，使当前 PCB、页表与执行现场一致。汇编按 ABI 恢复新上下文。

**提示词**

> 按 `proc.h` 的字段布局实现 `cpu_idle`、`schedule`、`proc_run` 和 `switch_to`。保护 `current` 和上下文切换的临界区，保留原中断状态；按 Sv39 的 MODE 与页表根物理页号写 `satp`，再刷新 TLB。对照 `struct context` 保存和恢复 `ra`、`sp`、`s0`–`s11`，检查首次进入 init，以及切回已保存现场的线程。

**实现分析。** `schedule()` 决定下一线程，`proc_run()` 负责执行切换。Lab4 的主动调度从 idle 起步，评分线程也显式调用 `schedule()`。调用约定使调用者处理需要跨调用保留的 caller-saved 寄存器；汇编保存继续执行所需的返回地址、栈和 callee-saved 寄存器。Trap frame 额外包含陷入返回需要使用的通用寄存器与 CSR。

## 扩展练习与原理对照

1. **保存和恢复中断。** `local_intr_save()` 读取 `sstatus.SIE` 并清除该位，同时记录原值。`local_intr_restore()` 只在原先开启时重新置位。嵌套进入 `schedule()`、`proc_run()` 时，内层看到的中断状态为关闭，因此恢复时保持外层的临界区。
2. **多级页表。** Sv32、Sv39、Sv48 分别采用两、三、四级页表。每一级的基本操作是按虚拟页号分段取索引，检查条目，沿非叶子项的物理页号进入下一层。Sv39 的两段中间级查找代码采用相同逻辑。当前以 `create` 区分纯查询与创建，接口便于共用遍历。页表支持更多层级或并发后，可以保留共享遍历逻辑，将分配和回滚职责单独提取。
3. **原理对应。** 页表权限与 TLB 对应地址转换、保护与缓存一致性；`proc_struct` 对应 PCB；独立内核栈和 `context` 对应线程可恢复的执行现场；`schedule()` 对应就绪实体选择。实验代码在单 hart 上用中断屏蔽管理临界区，跨 CPU 同步还需要锁和相应的 TLB 同步机制。
4. **后续覆盖。** 用户进程的独立地址空间、按需分页、页面换入换出、时间片抢占、多核调度、进程退出回收，以及退出后如何防止旧 PID 引用被误用。
