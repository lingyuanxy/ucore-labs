### 原理与疑问

交叉编译器运行在 x86 主机上，生成 RISC-V 指令；QEMU 模拟 RISC-V 机器以执行这些指令。GDB 在后续步骤中控制模拟 CPU 并查看寄存器、内存与指令。

`bin/kernel` 是 ELF 文件，保留调试所用的符号等信息；Makefile 使用 objcopy 生成的 `bin/ucore.img` 是供本实验 loader 加载的原始二进制镜像。二者来自同一次编译，但用途不同。

## 当前概念疑问：为什么操作系统实验需要 GCC？

本人提出疑问后暂停后续单步操作。操作系统内核同样由源码构建，本实验中的 C 与汇编文件需要经过编译、汇编和链接，形成 RISC-V 机器指令，才能由模拟 CPU 执行。

- GCC：构建过程中使用的编译工具，将 C 源码翻译，并驱动相关汇编等步骤。
- QEMU：模拟计算机，执行已构建的内核。
- GDB：控制运行、查看寄存器和内存，帮助理解启动流程。

本次截图中出现的是 GDB；前一步版本核对中出现的是 GCC。两者是不同工具。本实验关注启动原理，编译器是构建实验内核所需的基础工具。

这条 auipc 将自身地址与零偏移相加，写入 t0，为后续计算地址准备基准。

### 已完成：addi 准备设备树地址

```gdb
info registers pc t0 a1
si
info registers pc t0 a1
x/i $pc
```

本人截图确认：执行前 `pc=0x1004`、`t0=0x1000`、`a1=0`；执行后 `pc=0x1008`、`t0=0x1000`、`a1=0x1020`（十进制 4128）。下一条指令为 `csrr a0,mhartid`。实际变化符合 `a1=t0+32=0x1000+0x20=0x1020`。

![本人单步执行addi的截图](images/04-reset-addi.png)

已通过所安装 QEMU 4.1.1 源码的 `hw/riscv/virt.c` 核对：复位指令与跳转地址共占 32 字节，设备树紧接其后，位于复位区域基址加 32 的位置。设备树是描述 CPU、内存和外设等硬件信息的数据结构，将其地址放入 a1，供启动固件使用。此说明依据 QEMU 源码；本人目前尚未通过内存查看验证设备树内容。

### 已完成：csrr 读取硬件执行单元编号

```gdb
info registers pc a0 a1
si
info registers pc a0 a1
x/i $pc
```

本人截图确认：执行前 `pc=0x1008`、`a0=0`、`a1=0x1020`；执行后 `pc=0x100c`、`a0=0`、`a1=0x1020`。下一条指令为 `ld t0,24(t0)`。

`csrr a0,mhartid` 把 mhartid 特殊寄存器保存的硬件执行单元编号读取到 a0，供启动固件使用。读取结果为 0，与原值相同，结合 PC 的前进确认单步完成。

![本人单步执行csrr的截图](images/05-reset-csrr.png)

原理依据：[RISC-V 特权规范中的 mhartid](https://docs.riscv.org/reference/isa/priv/machine.html)。

### 已完成：ld 从内存读取跳转目标

```gdb
info registers pc t0
x/1gx 0x1018
si
info registers pc t0
x/i $pc
```

本人截图确认：执行前 `pc=0x100c`、`t0=0x1000`。`x/1gx 0x1018` 输出 `0x1018: 0x0000000080000000`；执行一次 `si` 后，`pc=0x1010`、`t0=0x80000000`（十进制 2147483648），下一条为 `jr t0`。

`ld t0,24(t0)` 使用执行前 t0 的值计算读取位置：`0x1000+24=0x1018`，从该位置读取 8 字节，写回 t0。内存查看和加载后的寄存器值互相吻合。此时尚未执行跳转。

`x/1gx` 表示以十六进制查看一个 8 字节的数据单元。

![本人查看内存并单步执行ld的截图](images/06-reset-ld.png)

指令原理依据：[RV64I 的 LD 指令](https://docs.riscv.org/reference/isa/v20240411/unpriv/rv64.html)。

### 已完成：jr 跳转至 OpenSBI 入口

```gdb
si
info registers pc t0 a0 a1
x/8i $pc
```

`jr t0` 跳转至 t0 指定的位置。当前 t0 为 0x80000000，预期执行后 PC 为 0x80000000；a0 与 a1 保留作为固件启动参数。QEMU 4.1.1 的 virt 启动代码在 DRAM 起始地址 0x80000000 加载默认 OpenSBI 固件；内核位于另一个地址 0x80200000，稍后再观察固件交接至内核的过程。

本人截图确认：执行一次 si 后 `pc=0x80000000`、`t0=0x80000000`、`a0=0`、`a1=0x1020`。固件入口第一条指令为 `csrr a6,mhartid`，其后为 `bgtz a6,0x80000108`。本步完成复位入口到固件的实际跳转。

### 已完成：在内核交接前设置硬件断点

引导时对本机 QEMU 4.1.1 配套 OpenSBI 固件进行只读反汇编，确认 S 模式交接使用的 mret 在 `0x80005036`。该处对应 sbi_hart_switch_mode 设置 mstatus、mepc、S 模式相关寄存器后的指令。

```gdb
x/i 0x80005036
hbreak *0x80005036
continue
info registers pc mepc mstatus a0 a1
x/i $pc
```

本人截图确认：`x/i 0x80005036` 显示 mret；硬件断点 1 命中，PC 为 0x80005036。mepc 为 0x80200000，mstatus 为 0x8000000000006800（GDB 解码 MPP=1），a0=0，a1=0x82200000。此时 mret 尚未执行。

硬件断点在指定指令执行前停住；continue 让中间初始化正常运行，直到命中断点。mepc 保存本次 mret 的目标地址，mstatus 中的 MPP 字段选择执行后的特权级，1 对应 S 模式。

![本人命中OpenSBI交接前断点的截图](images/09-opensbi-before-mret.png)

a1 从进入固件时的 0x1020 变成 0x82200000。已核对 OpenSBI v0.4 的 QEMU virt 配置，FW_JUMP_FDT_ADDR=0x82200000；启动汇编把设备树复制至下一阶段所用的位置，交接函数将下一阶段参数放入 a1。本人的截图记录了参数前后变化，中间复制循环未逐条单步。

原理依据：[OpenSBI v0.4 的 sbi_hart_switch_mode](https://github.com/riscv-software-src/opensbi/blob/v0.4/lib/sbi/sbi_hart.c)、[RISC-V 特权规范](https://docs.riscv.org/reference/isa/priv/machine.html)。

### 已完成：执行 mret 进入内核

```gdb

```

本人截图确认：执行后 PC 为 `0x80200000 <kern_entry>`，GDB 对应到 `kern/init/entry.S:7` 的 `la sp,bootstacktop`。sp 为 0x8001bd80，a0=0，a1=0x82200000。入口前三条机器指令为 auipc sp,0x3；mv sp,sp；j 0x8020000a。

## 第五步：内核启动栈与 C 入口（已完成）

### 已完成：设置内核自己的启动栈

```gdb
info address bootstacktop
si
info registers pc sp
si
info registers pc sp
x/i $pc
```

本人截图确认：bootstacktop 地址为 0x80203000；第一条单步后 PC=0x80200004、sp=0x80203000；第二条单步后 PC=0x80200008、sp=0x80203000；下一条为 `j 0x8020000a <kern_init>`。

源码的 la sp,bootstacktop 在本次构建中展开为两条指令：auipc sp,0x3 与 mv sp,sp。第一条使用自身地址 0x80200000 加上 0x3000，令 sp=0x80203000；第二条对应零偏移，sp 数值保持不变。

bootstack 在内核的数据区预留 2 页，共 8192 字节，sp 设为 bootstacktop，为之后的函数调用和 C 代码提供内核自身的栈空间。

![本人设置启动栈的截图](images/11-kernel-stack.png)

符号表核对结果：bootstack=0x80201000，bootstacktop 和 SBI_CONSOLE_PUTCHAR 同为 0x80203000。栈顶边界与紧接其后的数据对象共享地址，GDB 的符号注释不影响 sp 已指向栈顶的结论。

### 已完成：核对 memset 的清零范围与调用参数

```gdb
info address edata
info address end
si 8
info registers pc sp a0 a1 a2
x/i $pc
```

本人截图确认：edata 和 end 都在 0x80203008；执行 si 8 后 PC=0x80200022，当前指令为 jal 0x80200490 <memset>。sp=0x80202ff0，a0=0x80203008，a1=0，a2=0。这八条完成地址计算、栈帧分配、参数设置和 ra 保存；尚未进入 memset。

本人符号查询和寄存器结果已互相核对：edata=end，清零长度 a2=0。当前最小内核没有占用该清零区间的数据，零长度调用也是合理情况。
