## 构建、启动与验证

在 WSL 中进入主仓库的 `lab2` 目录：

```bash
cd lab2  # 当前位于 ucore-labs 根目录时执行
make
make qemu
make grade
make verify
make trace
make check-preservation
```

也可以留在主仓库根目录，执行 `make -C lab2`、`make -C lab2 qemu` 等。QEMU 未退出前不要把后续命令输入其控制台。

QEMU 退出：Ctrl+A，松开后按小写 x。默认内核运行 Buddy 和 SLUB 自检。旧版 `PMM=best_fit` 切换入口不适用于这份固定选择 Buddy 的源码；三种后端的比较通过搭档已有的独立测试驱动完成。

`make verify` 完成原版内核三种 RAM 配置启动、原版专项驱动三种 PMM 后端测试、原版课程评分，并在前后校验全部受保护原始文件。评分结果单独记录；验证流程完成不等于课程评分满分。

`make grade` 在独立的 O0 调试验证配置中，于 PMM 初始化前用 GDB 选择 Best Fit，并执行原版检查，实测 **20/20**。日常 Buddy 选择不变。`make grade-original` 直接按原版默认 Buddy 运行评分，可复现 **10/20**；两个入口各自保留真实日志。详见 [问题清单](问题清单.md)。

本轮新增 `make audit-page-init`（六种解析后输入达到预期）和 `make audit-allocators`（明确复现参考 First Fit 两处尾插缺陷，同用例 Best Fit/Buddy 通过）。后者成功退出表示复现成功，不是所有分配器边界通过；它不包含在旧 `verify` 的通过结论中。完整手册对照见[任务审查表](report/requirements-audit.md)。

其他电脑复制 `Makefile.local.example` 为 `Makefile.local` 后填写自己的 GCCPREFIX、GDB、QEMU。原版 `code/Makefile` 内的 viewfinder 路径完整保留；本机通过命令行变量覆盖，不改写原文件。

## 调试

两个 WSL 终端分别运行 `make debug` 和 `make gdb`。VS Code 的 `uCore lab2 (preserved partner code)` 配置连接已启动的 QEMU，使用本机已安装的 `/usr/bin/gdb-multiarch`。

`make trace` 自动采集宿主页表、宿主 TLB 和来宾指令三组记录，读取当前 ELF 符号重新设置断点。新日志放在 `validation/2026-10-25/`，搭档原来的 GDB 记录保持不变。

搭档报告中的 `/opt/qemu-4.1.1` 实为 7.0.0 的说明属于他的机器。本机这个路径实际为 4.1.1，两份环境记录应分别阅读。
